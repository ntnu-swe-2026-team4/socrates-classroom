C2 · migration 編號相撞，而且合併後不會有 conflict

001_init.sql 兩邊都沒動，所以 git 對 migrations 目錄一個衝突都不報，直接產生：

006_topic_classroom        006_community.sql
                           007_teacher_key_entries … 011_usage_quota

而且內容互相踩：003_accounts_solo.sql 做 ALTER TABLE users DROP COLUMN role，002_capabilities.sql 卻用 UPDATE users SET can_manage_classes = 1 WHERE role = 'teacher' 回填；is_admin 在兩支 migration 都被 ADD COLUMN。順序一換就炸，順序對也可能炸。

C3 · only_student 的語意是相反的

web-next 保留 only_student（owner 不能用自己的帳號加入自己的班級，責任歸屬考量，docs/accounts.md 有寫）；216f62f 把它刪掉，改成「任何已登入身分都能加入，老師用 test slot 自測」。API 錯誤碼表、前端 i18n（join_only_student 三語）、兩邊的測試都咬住這個字串。

C4 · /t/setup 的生死

web-next 刪了 /t/setup（改成「創建課程 → 直接進教室頁編輯」）；216f62f 把它拆成 classroom → 議題集 → 開活動 三步，而且 POST /api/classrooms 改成只建班級（活動走 POST /api/classrooms/:id/activities）。這不是文字衝突，是前端呼叫端一定要重寫。

C5 · thread／report 的 key 換代價

216f62f 把 thread key 改成 {activityId}:{participantId}（ActivityInfo.participantId 是 WS thread 名的一半，apps/web/src/routes/dialogue.tsx 要等 info resolve 才掛 socket）。AGENTS.md 明寫「ws/protocol.ts 的協定與 tests/chat.test.ts 絕不能壞」——這是本合併的最高風險點，do/chat.ts、ws/sockets.ts、useDialogue.ts、chat.test.ts 要一起看。

C6 · admin 兩套 UI／兩套 API

web-next：/admin tabbed console（overview／user table／schools／teacher 開通）；216f62f：/admin/users ＋ routes/admin.ts（is_admin、停用即踢線、session_version）。兩份都要收斂成一個 endpoint 組 ＋ 一個 UI。
